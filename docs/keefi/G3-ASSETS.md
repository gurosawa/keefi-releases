# KEEFI 자산 원장과 평가 자료

자산 원장은 조회한 수량·평가액·이벤트·가격·주문 관측과 그 출처·시각·완전성을 보존한다. 기록이 존재한다는 사실만으로 모든 거래·입출금의 수집이나 실제 계좌 대사가 완료되었다고 판단하지 않는다.

## 현재 저장 형식

| 항목 | 현재 계약 |
|---|---|
| 최신 상태와 장기 기록 | `assets-current.keefi`, `assets.keefi` |
| 컨테이너 | 8바이트 `KEEFIAST`, version 1, reserved 0, 24바이트 nonce, 암호문 길이를 포함하는 40바이트 헤더 |
| 암호화 | 헤더 전체를 additional data로 인증하는 XChaCha20-Poly1305 |
| 저장 키 | 금고의 랜덤 원장 root key에서 `KEEFI/assets-ledger/v1` domain으로 유도 |
| 내부 payload | schema 1·2를 읽고 schema 3의 수집 상태·이전 증거를 구분 |
| 상한 | 파일 16 MiB, 스냅숏 2,048개, 이벤트·가격·주문 관측 각각 20,000개 |

현재 파일명·저장 domain과 구형 읽기·이전의 경계는 [금고·원장 형식](VAULT-FORMAT.md)을 따른다. 저장용 domain은 계좌·이벤트의 논리 식별 domain과 다르다. 이전 프로필의 identity와 원본 암호문 증거를 새 값으로 추정 교체하지 않는다.

## 기록과 실패

최신 상태 캐시의 교체와 장기 기록의 추가는 별도 동작이다. 장기 파일이 상한에 이르면 인증된 암호화 보관 파일을 먼저 만들며, 보관 파일 256개 상한은 오류로 알리고 자동 삭제하지 않는다.

저장은 기존 암호문의 digest를 비교하고 같은 폴더의 암호문 임시 파일을 검증한 뒤 교체한다. 교체 뒤 디스크 반영·읽기 확인 실패에는 새 파일이 이미 존재할 수 있다. 모든 저장 실패가 이전 파일 보존을 보장하는 것은 아니다. 잠금은 원장의 보호 키와 평문 상태를 지우지만 Qt 문자열의 모든 사본을 완전 소거한다는 보장은 아니다.

금고와 원장은 하나의 파일이나 단일 트랜잭션이 아니다. 금고만 다른 시점으로 복구하면 해당 원장의 키가 없을 수 있다. 기록 이동·복원 범위는 [기록 이동](G4-RECORD-TRANSFER.md)을 따른다.

## 현재 평가와 저장 자료

저장 스냅숏은 현재 연결과 인증정보 결합이 일치하는 경우에만 복원 입력으로 사용한다. 이것만으로 첫 해제 화면에 현재 값처럼 표시할 수 있는 것은 아니다. 첫 조회, 같은 실행의 재해제, 현재·참고·미평가, 합계와 기간 손익의 조건은 [평가 정책](VALUATION-POLICY.md)을 따른다. 미조회나 누락을 0으로 채우거나 미실현손익을 순자산에 다시 더하지 않는다.
