# KEEFI 키움 REST 계좌 식별과 조회 경계

현재 키움 REST 연결은 `live`·`domestic_equity`·`KRW` 조합을 사용한다. KEEFI는 조회 전용이다. 과거 `paper` 연결과 미확정 주문 기록을 읽는 호환성은 현재 모의 조회나 주문 지원을 뜻하지 않는다.

## 발견 계좌와 확인값

토큰 발급 후 `ka00001` 계좌 응답의 `acctNo`를 확인한다. 구현은 원문 ASCII 숫자 10자리를 요구한다. 설정의 선택적 계좌번호 확인값도 같은 형식으로 받아 발견 계좌와 정확히 비교하며, 이 값으로 인증된 계좌를 바꾸지 않는다.

계좌번호와 주문번호는 금액이 아니다. 숫자로 변환하거나 선행 0을 없애지 않는다. 금액의 부호·padding 정규화 규칙을 식별자에 적용하지 않는다.

계좌 범위는 선택된 identity scheme의 키움 계좌 domain, `kiwoom`, 환경, 발견한 원문 계좌번호를 각각 길이로 구분한 SHA-256이다. domain 선택과 기존 scope의 보존은 [금고의 식별자 계약](VAULT-FORMAT.md#기록의-식별자와-증거-보존)을 따른다. 계좌 선택에는 임의 handle과 마스킹 label을 제공한다.

## 조회와 기록의 해석

예수금·D+1/D+2 추정치·주문 가능액·출금 가능액·보유 평가액은 다른 항목이다. 미제공 금액이나 수수료를 0으로 만들지 않는다. 조회 성공만으로 거래 권한이나 전체 과거 손익의 완전성이 확인되는 것은 아니다.

과거 주문의 대상 번호, 변경 접수번호, 모주문 번호는 서로 다를 수 있다. 금고는 참조·수량 모드·출처를 구분해 보존하며 원문 키·계좌번호를 미확정 주문 기록에 넣지 않는다. 상세 저장 계약은 [금고 형식](VAULT-FORMAT.md)을 따른다. 형식 호환은 주문의 최종 완료나 현재 거래 실행을 의미하지 않는다.

키·토큰·원문 계좌·연속 조회 키는 보호 버퍼에서 다루고 세션 종료 때 정리한다. 요청과 JSON 파싱에서 생기는 모든 임시 메모리 사본까지 완전 소거한다고 보장하지 않는다. 실제 계좌 확인과 합성 시험의 범위는 [검증 상태](VERIFICATION-STATUS.md)에서 구분한다.
