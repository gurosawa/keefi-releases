# KEEFI LS증권 계좌 식별과 조회 경계

현재 LS 연결은 `live`·`domestic_equity`·`KRW` 조합을 사용한다. KEEFI는 조회 전용이며, 이 문서의 계좌 식별·기록 호환 설명은 주문 지원 안내가 아니다. 과거 `paper` 기록은 [금고 형식](VAULT-FORMAT.md)의 호환 규칙에 따라 보존한다.

## 인증된 계좌의 식별

- 어댑터는 토큰 발급과 계좌 확인을 별도 단계로 처리한다. 토큰 발급만으로 잔고 조회나 모든 권한이 확인되었다고 판정하지 않는다.
- `CSPAQ12200` 계좌 응답의 `AcntNo`를 원문으로 확인한다. 설정의 선택적 계좌번호 확인값은 발견한 계좌와 정확히 비교하는 값이며, 다른 계좌를 선택하는 값이 아니다.
- 계좌번호는 숫자로 변환하거나 선행 0을 없애지 않는다. 구현은 공백 없는 printable ASCII, 최대 20자를 요구하며 키움의 숫자 10자리 규칙을 적용하지 않는다.
- 계좌 범위는 선택된 identity scheme의 LS 전용 domain, 환경, 원문 계좌번호를 각각 길이로 구분한 SHA-256이다. 새 프로필과 이전된 프로필의 domain 선택은 [금고의 식별자 계약](VAULT-FORMAT.md#기록의-식별자와-증거-보존)을 따른다.
- 계좌 선택에는 임의 handle과 마스킹 label을 제공한다. 키·토큰·원문 계좌는 보호 버퍼에서 다루지만, Qt 파싱 과정의 모든 임시 메모리 사본까지 완전 소거한다고 보장하지 않는다.

## 조회 자료와 과거 기록

예수금·주문 가능액·출금 가능액은 서로 다른 필드다. 누락된 금액은 0으로 만들지 않는다. 보유 평가액을 예수금으로 합치거나, 현금 보유 분류를 확인하지 못한 행을 현금 보유로 승격하지 않는다.

과거 LS 미확정 기록의 수량·참조·계좌 범위는 [금고 형식](VAULT-FORMAT.md)의 LS 계약을 따른다. 이 계약을 읽을 수 있다는 사실은 현재 주문·정정·취소 기능이나 과거 주문의 최종 성공을 증명하지 않는다. 실제 LS 계좌의 성공 범위는 [검증 상태](VERIFICATION-STATUS.md)와 구분해서 판단해야 한다.
