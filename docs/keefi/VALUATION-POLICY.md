# FINIX 평가 정책 v2 — G7

갱신: 2026-10-21. **확정한 G7 평가 정책 v2.** 현재·과거 자산 평가의 기준이며 구현·합성 검증·실계좌 대사는 별도 증거다. 최초 문서는 build 47 코드에서 규칙을 뽑았고 build 49 다리·build 50 R4 정정을 반영했다. 아래는 정책 v2에 채택한 규칙이며, 검증 현황은 [검증 상태](VERIFICATION-STATUS.md), 결정·회귀 기준은 [정책 결정 기록](G7-POLICY-DECISIONS.md)을 따른다.

## 0. 범위·단위·식별

- 기본 통화는 KRW이며 실전(`live`)·Solana 메인넷(`mainnet`) 연결만 조회·평가한다. 2026-10-21 소스부터 모든 모의·테스트넷(`paper`·`demo`·`testnet`) 연결의 지원을 종료한다.
- 예전 모의·테스트넷 연결은 금고 읽기와 재저장 호환을 위해 보존한다. 자동으로 실전으로 바꾸거나 잔고·가격을 조회하지 않으며 평가 합계에 넣지 않는다. `계좌·연결`에서 삭제할 수 있고 별칭·인증정보 변경과 신규 등록은 허용하지 않는다. 기존 암호화 주문 대사 기록은 읽기 호환을 유지한다.
- 금액·수량·가격은 정확한 문자열 십진수다. 부호를 제외한 정수 1~80자리, 소수 0~80자리를 허용한다. 지수 표기는 수집 경계에서 정규 문자열로 바뀐 뒤 검증한다.
- 코인은 거래소 정식 자산 ID, Solana 토큰은 `solana:<Mint>`를 유지한다. 심볼·표시 이름·아이콘은 식별자나 가격 연결 키가 아니다.
- 탐색의 CoinGecko·네이버·Nasdaq 값은 평가 입력에 연결하지 않는다. 허용된 업비트·Binance·Jupiter 공개 가격과 공급자의 공식 보고 평가금액만 사용한다.
- 근거는 source, URL, scope, 원본 시각, 수신 시각, complete를 보존한다. 원본 시각 0은 미제공이며 새 원본 시각을 만들어 넣지 않는다.

## 1. 최신성 — 자산 평가 180초

잔고·행·현재 가격 근거는 complete이고 source와 scope가 있으며, `0 < 수신 ≤ 평가 시각`, `평가 시각 − 수신 ≤ 180초`여야 한다. 원본 시각은 0이거나 `0 < 원본 ≤ 평가 시각`, `평가 시각 − 원본 ≤ 180초`다. 현재 화면과 과거 자산 탭은 같은 180초를 쓴다. 과거 값은 **저장 당시 평가 시각**에서 판정한다.

- 계좌 스냅숏은 balanceComplete, 유효 근거, 양의 잔고 시각과 180초 조건을 함께 요구한다. 실패하면 전체 판정을 incomplete로 둔다.
- 개별 행은 자기 근거·수량·보고 금액으로 판정한다. 불완전 계좌의 정상 최신 행은 확인된 부분합에 남는다. 계좌 불완전 때문에 정상 행 전체를 0이나 미평가로 바꾸지 않는다(build 50 R4).
- 개별 행의 잔고 근거가 오래되면 그 행은 미평가다. 오래된 **가격**을 참고 평가로 쓰는 규칙과 다르다.
- 과거 입출금 환율을 쓰는 `flows()`의 60초 기본값은 이 자산 탭 정책으로 자동 변경하지 않는다. G7 시간축·수익률 작업에서 별도 검증한다.

## 2. 잔고와 공급자 보고 금액

| 연결 | 평가하는 입력 | 별도 가산하지 않는 입력 |
|---|---|---|
| 업비트·빗썸·Binance·OKX 현물 | free + locked 보유 수량 | 주문의 명목금액 |
| Binance USDⓈ-M 선물 | 자산별 공식 equity | 같은 valuationGroup의 Holding/Cash/Liability, 포지션 명목금액, 미실현손익 |
| 증권 | 공식 종목 평가금액과 예수금 | 매수가능금액·출금가능금액·표시 손익 |
| Solana 지갑 | SOL, SPL·Token-2022의 Mint별 정확한 수량 | 범위 밖 스테이킹·압축 자산·비공개 잔고 |

증권 신용·대출 보유, 예수금 누락 등으로 스냅숏의 완전성이 떨어지면 정상 종목 평가액은 부분합에 남고 완전 순자산은 정하지 않는다. 보고 평가금액이 있으면 수량×공개 주가 대신 그 금액을 보고 통화에서 KRW로 환산한다. 보고 통화가 빈 경우 KRW로 추정하지 않는다. USD 환산 경로가 없으면 미평가로 남긴다.

## 3. 가격 자격과 선택 순서

### 공개 가격의 자격

직접·참고 가격은 `public:` scope이며 양수 가격, complete, source, URL이 모두 있어야 한다. 수신 시각은 양수이며 평가 시각 이하, 원본 시각은 0 이상이며 평가 시각 이하다. 원본이 수신보다 앞서는 서버·PC 시계 차이는 **최대 2,000ms까지** 허용한다. 수신기가 이미 허용하던 범위와 평가기를 build 52에서 일치시킨 결함 수정이다. 원본이 **평가 시각보다 미래**이면 이 허용 범위 안이어도 아직 평가하지 않는다. 원본·수신 시각을 고쳐 쓰거나 180초·24시간 유효시간을 연장하지 않는다. 개인 계좌가 붙인 사적 quote는 공통 환산 가격에서 제외한다. 증권사의 공식 보고 평가금액은 quote와 다른 입력이므로 계속 사용한다.

직접 후보의 선택 키는 **원본 시각, 없으면 수신 시각**이다. 최신 키의 후보들만 비교하고 정규화된 가격이 다르면 그 직접 경로를 충돌로 처리한다. `1`과 `1.0`은 같은 가격이다. 오래된 후보의 충돌이 더 최신의 정상 후보를 막지 않으며 입력 순서로 결과가 달라지지 않는다.

### 환산 순서

1. 자산과 기준 통화가 같으면 원 수량을 쓴다. 실제 수량 0은 가격 없이 0원이다.
2. 보고 평가금액이 있으면 그 명시 통화를 같은 환산 순서로 변환한다.
3. 최신·유효한 직접 공개 가격이 있으면 수량을 곱한다.
4. 직접 가격이 없거나 충돌하면 독립적인 허용 교차 경로를 시도한다.
5. 현재 값이 없으면 5절의 참고 가격을 시도한다. 끝까지 없으면 미평가다.

### 허용 교차 경로와 시각

- 일반 코인: Binance 자산/USDT × 업비트 KRW-USDT. exact scope는 `public:binance:<자산>USDT`, `public:upbit:KRW-USDT`다.
- Solana Mint: Jupiter Mint USD와 정식 Circle USDC Mint USD를 사용한다. exact scope는 `public:jupiter:price:<Mint>`다.
  - **지갑 수집 단계(2026-10-21 T2-b 수정):** Jupiter 가격의 원본 시각은 `blockId`의 블록 시각이다. 수집기는 블록 시각이 24시간 안이면 원래 시각 그대로 quote로 넘기고, 180초 초과 여부는 평가기가 판정한다. 180초를 넘으면 참고 평가(합계 제외), 24시간을 넘으면 quote를 만들지 않는다. 이전에는 수집기가 180초를 넘은 가격을 버려 참고값도 없이 미평가가 됐다.
- Solana의 USDC/KRW 다리는 업비트 KRW-USDC와 Binance USDC/USDT × 업비트 KRW-USDT 중 원본 시각이 늦은 쪽을 쓴다. 동률이면 업비트다(build 49 유지).
- 각 다리는 source/URL/정확한 scope/complete/양수 가격과 양의 원본·수신 시각을 **개별 검증**한다. 미래·누락 시각은 다른 다리의 최소 시각에 가려 유효해질 수 없다.
- 각 다리의 최신 원본 시각에서 다른 가격이 충돌하면 그 다리를 쓰지 않는다.
- 파생 근거의 원본과 수신 시각은 실제 2개, 3개 또는 4개 다리의 각각 최솟값이며, 사용한 모든 다리 근거를 보존한다. 최종 결과도 현재 값이면 180초 안이어야 한다.
- USDT는 별도 교차 경로가 없고 직접 KRW-USDT를 쓴다. USDT·USDC를 1 USD로 고정하지 않는다.

### Solana 계산 순서·버림

`단위 KRW 가격 = truncate24(Mint USD × 선택한 USDC KRW 가격 ÷ USDC Mint USD)`로 정한 뒤 보유 수량을 곱한다. truncate24는 소수 24자리에서 버림이며 반올림이 아니다. `(Mint USD ÷ USDC USD)`를 먼저 버리는 순서와 다르다. 예를 들어 Mint=1, USDC=3, USDC KRW=1000이면 단위 가격은 `333.333333333333333333333333`이다.

## 4. 합계·중복·정밀도

- Equity와 그 equity 그룹에 속하지 않은 Holding/Cash/Liability를 합계 대상으로 둔다. Liability는 음수다.
- BuyingPower/Withdrawable/PositionNotional/UnrealizedPnl/ProviderPnl과 equity에 포함된 기초 행은 합계 제외다.
- 중복 accountScope의 뒤 스냅숏은 계산에서 제외하고 전체 incomplete로 둔다. 중복 component ID는 사유가 있는 미평가 행으로 남긴다. 동일 valuationGroup+asset Equity를 이중 가산하지 않는다.
- 확인된 부분합은 평가할 수 있는 포함 행의 정확한 합이다. 모든 스냅숏·포함 행·연결 조회 상태가 완전할 때만 완전 합계를 정한다.
- 개별 값이 정수·소수 각 80자리를 초과하면 그 값은 미평가다. 합계는 양수·음수 항을 먼저 상쇄하고 **최종 합에** 같은 상한을 적용하므로 입력 순서에 따라 달라지지 않는다. 전체 합이 표현 범위를 넘으면 **총합을 unavailable**로 두고 유효한 개별 행은 보존한다. 넘기 직전 부분합이나 0을 총합으로 대신 표시하지 않는다. 그룹 수량·평가액과 참고 평가 합계도 같은 규칙을 쓴다.
- 화면 총합이 무효이면 `자료 부족`으로 표시한다. 금액은 계산 중 반올림하지 않는다.

## 5. 가격 참고 평가 — 최대 24시간

현재 가격을 못 구했더라도 공개 직접·교차 가격의 구조·시각 자격이 유효하고, 원본(없으면 수신)과 수신이 모두 평가 시각 기준 **24시간 이내**면 참고 가격으로 표시할 수 있다. 경계 24시간은 허용하고 24시간+1ms는 허용하지 않는다. 최신 가격과 달리 기준 시각을 표시하며 합계·자체 손익·성과에는 포함하지 않는다.

직접 참고 후보가 충돌해도 독립적인 유효 교차 참고 경로를 시도한다. 24시간이 지난 값, 미래 값, 출처·URL이 없는 값은 참고액으로도 남기지 않는다. 참고 가격의 최대 나이가 없던 build 50 이전 규칙을 변경한 것이다. 공개 시세 수신·스트리밍으로 기존 원본 시각을 새로 쓰지 않는다.

## 6. 자산 그룹·보유 판정·정렬

- KRW는 `cash:KRW`, 국내주식은 `stock:KR:<코드>`, Solana SOL은 `solana:native`, 토큰은 `solana:<Mint>`, 거래소 코인은 `exchange:<정식 자산 ID>`로 묶는다.
- 거래소 SOL·USDC와 지갑 SOL·USDC는 별도 identity를 유지하며 이름에 거래소/지갑을 구분한다. 같은 심볼이라는 이유로 합치지 않는다.
- 그룹 수량은 일반 NotCounted를 빼고 합한다. 사용자 평가 제외 행은 보유 자체가 없어지는 것이 아니므로 수량을 포함한다. 부채는 음수다.
- 유효한 비0 수량·보고금액이 하나라도 있으면 Held다. 비0가 없고 비정상 값 또는 불완전한 0 근거가 있으면 NeedsCheck다. 모두 확실한 0이면 Zero다.
- 선물 Equity 0은 완전 잔고·명시적 0 PnL·Fresh 값일 때만 Zero다. 열린 포지션의 별도 NotCounted 행은 보존한다.
- 기본 정렬은 Fresh 값 그룹 평가액 내림차순, 그 밖의 그룹, 확인된 Zero 그룹 순서다. 동률은 canonical identity 순이다.

## 7. 표시·비중·필터

- 총액·행·상세 원화 금액은 절댓값 기준 half-up으로 원 단위 표시한다. 계산·진단 원문은 정확한 원본 문자열을 보존한다.
- 비중은 최신·부채 아님·양수 값만 분자로 합하고 같은 범위의 합을 분모로 사용한다. 필터로 분모를 바꾸지 않는다. 0.05% 미만 양수는 `<0.1%`, 그 밖에는 소수 첫째 자리로 반올림한다. 막대는 6그룹 이상이면 상위4+기타다.
- 소액 기준은 최신 업비트 KRW-USDT 가격인 **1 USDT**다. USD라는 이름으로 부르거나 1 USD와 같다고 가정하지 않는다.
- 소액 숨김은 전부 Fresh이고 수량 확인 필요·음수·미평가·참고·NotCounted가 없는 그룹에만 적용한다. 기준 가격이 없으면 비활성이다.
- 소액 필터는 전체 평가 합계를 바꾸지 않는다. 툴팁에서 범위를 명시한 원 부분합 S, 숨긴 합 H, 제외 후 표시 합 D=S−H를 보여준다.
- 미평가 숨김은 전부 Unvalued인 그룹에만 적용한다. 확인할 계좌·부분 평가·참고·0원·NotCounted를 숨김 대상으로 추정하지 않는다. 이 필터는 완전 판정을 바꾸지 않는다.

## 8. 사용자 평가 대상 제외

가격 근거가 없는 토큰도 기본은 미평가이며 원 수량을 유지한다. 사용자가 **유효한 canonical Solana Mint ID**를 명시적으로 평가 대상에서 제외하고 되돌릴 수 있다. 심볼·이름·잘못된 주소로 제외하지 않는다.

- `AssetValueRow.excludedByUser=true`, included=false, 값은 빈 값, 이유는 `사용자 평가 대상 제외`다. 진단 필드는 `excluded_by_user`다.
- 제외 행은 NotCounted로 표시하지만 보유 수량과 상세를 유지한다. 0원 평가를 만들어 넣지 않는다.
- 계좌 조회·잔고 완전성은 여전히 요구한다. 제외는 나머지 포함 행의 평가를 막지 않는다.
- 현재 표시된 평가에 제외 그룹이 있으면 제목은 완전할 때 `평가 대상 합계`, 미완료일 때 `평가 대상 부분합`이다. 저장 화면은 `마지막 확인 평가 대상 합계`다. 제외 건수·범위를 함께 표시한다.
- 목록 숨김과 평가 범위 제외를 혼동하지 않는다. 가격이 나중에 생겨도 명시적 선택의 해제 경로를 제공한다.

## 9. 업체 손익

업체 손익은 유효 숫자·통화·같은 계좌 scope와 complete/source가 있고, 잔고 시각·수신·원본(있으면)이 180초 안일 때만 표시한다. 어디에도 가산하지 않는다. 자체 미실현손익은 평가액−유효 원가이며 기록 창의 기존 계산만 사용한다. 기간 수익률은 기초·기말 대사와 외부 입출금이 완결된 구간에서만 가능하며 G7 시간축 단계 전의 자산 증가를 수익으로 표시하지 않는다.

## 10. 로딩·저장 화면·내보내기

첫 금고 해제는 저장된 값으로 현재 상태를 가장하지 않고 현재 잔고·가격 조회가 끝날 때까지 로딩한다. 15초는 지연 안내 기준이며 완료로 바뀌는 시간이 아니다.

동일 실행의 재해제는 직전에 검증한 연결·환경·시장·credential binding·계좌 scope가 같고 저장 평가가 완전할 때만 마지막 확인 화면을 쓴다. 저장 계산은 현재 연결과 맞는 스냅숏과 해당 scope/public quote만 고르고, 각 시각이 미래가 아님을 확인한 뒤 최대 저장 시각에서 180초로 평가한다. 저장 스냅숏이 있는 연결은 complete, 없는 연결은 not_read로 재구성하고 active=false로 둔다. 참고 목록은 저장 계산에 쓰지 않는다.

Python `--recorded`는 이 저장 **계산**을 검증하며 앱의 동일 실행·verified scope **표시 허가**를 증명하지 않는다. build 50 R3에 따라 초기 로딩/저장 화면에서는 현재 평가 진단 내보내기를 차단한다. 현재 부분합이 확정된 뒤에만 같은 입력·시각·행·헤드라인의 묶음을 내보낸다. 내보내기 도중 잠금은 R2의 세대 검증으로 해당 작업을 끝낸다.
